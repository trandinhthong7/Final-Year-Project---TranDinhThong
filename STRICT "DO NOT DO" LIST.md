1. Academic Tone and Perspective

MISTAKE: Writing in the first person ("I will build...", "My project...").

AI RULE: NEVER write in the first person. All text must be generated strictly in the formal third person (e.g., "This project aims to...", "The developer implemented...").

2. Missing Structural Elements

MISTAKE: Omitting mandatory academic sections.

AI RULE: ALWAYS include a "Keywords" section in the proposal or abstract.

3. Weak SMART Objectives

MISTAKE: Writing objectives that only focus on the software build (coding) and lack measurable metrics.

AI RULE: NEVER limit objectives to coding tasks. Objectives must reflect the full scope of the project (including research, evaluation, and testing). Every objective must strictly adhere to the SMART framework and contain a quantifiable, measurable metric.

4. Flawed Competitor Analysis

MISTAKE: Reviewing existing products without using standard academic frameworks.

AI RULE: ALWAYS use Nielsen’s 10 Usability Heuristics. When evaluating or comparing similar existing products, you must include a dedicated section that evaluates them strictly against Nielsen's heuristics.

5. Lack of Citations and Critical Evaluation

MISTAKE: Making claims in the Problem Statement or briefly summarizing methodology without academic backing.

AI RULE: NEVER leave claims unsupported. The background/problem statement must include required citations. The Methodology section must not just describe planned actions; it must compare, contrast, and critically evaluate available approaches using research citations.

6. Superficial LSEPI (Legal, Social, Ethical, Professional Issues)

MISTAKE: Covering LSEPI too briefly without references.

AI RULE: ALWAYS expand LSEPI discussions. These sections must be detailed, analytical, and heavily supported with relevant academic or legal citations (e.g., citing GDPR, BCS Code of Conduct).

7. Fake "Agile" Gantt Charts

MISTAKE: Claiming an Agile methodology but providing a linear, Waterfall-style Gantt chart with no overlapping tasks.

AI RULE: ALWAYS show concurrency in project planning. Any generated Gantt charts or timelines must clearly illustrate parallel front-end and back-end activities, logical interdependencies, and the iterative nature of Agile development.

8. Excessive "Screen Dumps" and Code Walls

MISTAKE: Pasting massive blocks of code or UI screenshots without explaining the "why."

AI RULE: NEVER use excessive screen dumps. Limit code snippets to essential logic. Every piece of code or UI shown must be accompanied by a critical evaluation that justifies the product development decisions using research from earlier sections.
